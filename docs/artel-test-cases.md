# Artel 전투 QA 테스트 케이스

대상: `codex/artel-combat-qa`의 SDK 연동, 치트 6개, 지속 행동 7개. 기준 구현: `e057a911`. 작성일: 2026-10-22.

이 문서는 실행할 TC이며 **아래 케이스의 실행 상태는 모두 미실행**이다. 기존 로컬 검증에서 일부 동작은 통과했지만, 원격 Artel 호출을 포함한 이 TC 전체를 통과한 것으로 간주하지 않는다. 기존 증거와 제약은 [사용법](artel-combat.md)의 검증 실행 항목을 참고한다.

## 공통 준비와 판정

- Unity 2022.3.34f1 에디터 또는 Windows Development Build에서 TitleScene으로 시작하고 Artel에 연결한다. 에디터와 개발 빌드는 실행 기록을 따로 남긴다.
- 테스트 전용 진행 데이터로 실행한다. `go_to_stage`/`unlock_stages`는 저장값을 변경하므로 기존 플레이 기록을 백업하고 종료 후 복원한다.
- 전투 TC는 별도 명시가 없으면 Slime 진입 후 대화·인트로가 끝나고 조작이 가능한 상태에서 시작한다. 이전 행동을 모두 중단하고 HP·게이지·방패를 재설정한다.
- 행동은 기본 `maxSeconds=15`로 시작한다. 장시간 TC만 별도 시간을 사용한다. 비교할 때 수동 이동·공격 입력은 하지 않는다.
- HP·자원은 HUD와 관찰 가능한 수치를 함께 기록한다. 적의 동시 피격·재생이 수치를 바꾸면 해당 구간을 제외하고 재실행한다. 거리는 플레이어와 적의 월드 좌표로 측정한다.
- P0: 진행 차단·입력 잔류·빌드 노출, P1: 핵심 기능, P2: 경계·장시간. 실패 시 영상, 호출 인자/응답, behaviorId, 씬, 전후 수치, 콘솔 로그를 첨부한다.
- 기존 `HitCollider.hitEffect` 미할당과 `CameraManager.Awake` 오류도 기록한다. 판정을 방해하면 차단으로 표시하고 성공 처리하지 않는다.

### TC-36 경계 매트릭스

최솟값·최댓값은 정상 입력으로 별도 확인하고, 범위 밖 값은 각각 독립 호출한다. 장면 조건 불충족으로 인한 거절과 인자 오류를 구분한다.

| 인자 | 허용 경계 | 거절 확인 예 |
|---|---|---|
| heal_player.amount | 1, 10000 | 0, 10001 |

## 실행 기록 양식

매트릭스·환경별 실행은 ID 뒤에 하위 식별자를 붙인다(예: TC-15-Golem-Windows). 상태는 미실행 / PASS / FAIL / 차단 중 하나로 기록한다.

| 실행 ID | 커밋/빌드·환경 | 실행일/담당 | 실제 결과·전후 수치 | 상태 | 증거/결함 링크 |
|---|---|---|---|---|---|
| TC-01-Editor | | | | 미실행 | |

우선 실행 순서: TC-01 → TC-03 → TC-15/16 → TC-07/12 → TC-20/22 → TC-29~32 → TC-37. 이후 나머지 기능·경계·릴리스·정상 진행 회귀를 수행한다. P0 실패가 남아 있으면 배포 승인하지 않는다.
